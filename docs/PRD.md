# areyougoingslop — Product Requirements Document

## Status
Draft v0.2 (MVP scoped)

## 1) Product Overview
**areyougoingslop** is a viral web app that estimates how AI-assisted a GitHub user’s **public** contributions are and presents a humorous **Slop Score (0–100)** with tiered roast copy.

Positioning: **playful + directionally credible**, not forensic proof.

---

## 2) Goals

### Primary Goals
- Generate a score for a GitHub username in <10s (p95 target for cached-or-warm paths).
- Produce a funny, screenshot-worthy result card.
- Show clear "why" behind score (signal breakdown).

### Secondary Goals
- Public leaderboard for discovery and sharing.
- Trend view in later versions.

---

## 3) Non-Goals
- Definitive attribution of AI-generated code.
- Private/org/internal repository analysis.
- Enterprise compliance or anti-cheat enforcement.

---

## 4) MVP Scope Decisions (Final)
- **Data source:** Public GitHub data only.
- **Org/private activity:** Excluded entirely.
- **Scoring scope:** User-level only (no repo-level in v1).
- **Leaderboard:** Default public.
- **Recency model:** Yes, use score decay (recent activity weighted higher).

---

## 5) User Flow
1. User enters GitHub username.
2. Backend fetches recent public activity.
3. Scoring engine computes score + tier + confidence + reasons.
4. UI renders result page and share card.
5. Optional: result is indexed in public leaderboard.

---

## 6) Scoring Model (v1)

### 6.1 Signals
1. **Commit Message AI Signals**
   - Mentions like `claude`, `copilot`, `cursor`, `devin`, `generated by`, etc.
2. **Velocity vs Volume**
   - Unusually large diffs in short intervals.
3. **Apathy Ratio**
   - Very large commit + very short/generic message (`fix`, `update`, `wip`).
4. **Churn Pattern**
   - Repeated large rewrites in same files over short windows.
5. **Prompt Crumbs**
   - Leftover AI text patterns in messages/metadata.

### 6.2 Score Decay (Recency Weighting)
Apply weighted recency buckets so recent behavior matters more:
- **0–30 days:** weight `1.0`
- **31–90 days:** weight `0.6`
- **91–180 days:** weight `0.3`
- **>180 days:** excluded from MVP calculation

This keeps score reflective of current behavior rather than old habits.

### 6.3 Output Contract
- `slop_score` (0–100)
- `tier` (5-level roast scale)
- `confidence` (`low` | `medium` | `high`)
- `top_signals[]` (human-readable reasons)
- `scoring_window` (e.g., last 180 days)

### 6.4 Tier Labels
- 0–10: **The Artisanal Masochist**
- 11–30: **The Tab-Key Athlete**
- 31–60: **The LLM Diplomat**
- 61–85: **The Agent Supervisor**
- 86–100: **The Unsupervised Slop Machine**

---

## 7) Functional Requirements
- Username input + validation.
- GitHub fetch service for user recent public activity.
- Scoring endpoint returning full output contract.
- Result page `/u/[username]`.
- Public leaderboard page.
- Shareable OG image generation.
- Basic caching and rate limiting.

---

## 8) UX/Tone Requirements
- Tone: witty, thoughtful, dev-native sarcasm.
- Roasts should be playful, not abusive.
- Every score must include concise explanation.
- Result card must be visually premium + memeable.

---

## 9) Trust, Safety, and Legal
- Clear disclaimer: **satirical heuristic, not factual detector**.
- "How scoring works" transparency page.
- No claims of certainty or misconduct.
- Respect GitHub API rate limits and data usage terms.

---

## 10) Success Metrics
- p95 score time <10s (with cache strategy).
- Share rate (results shared / searches).
- Return users (7-day).
- Leaderboard visits.
- Qualitative sentiment (funny + fair).

---

## 11) Risks & Mitigations
- **False positives:** expose confidence + reasons + clear disclaimer.
- **Sparse data users:** mark low confidence and avoid overconfident copy.
- **API limits:** cache aggressively and queue/background re-compute if needed.

---

## 12) Open Questions (Remaining)
- Minimum contribution count before issuing score?
- Should users be able to hide themselves from leaderboard?
- How often to refresh cached scores (6h, 12h, 24h)?
